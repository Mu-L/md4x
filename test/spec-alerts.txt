
# Alerts (GitHub-style admonitions)

The HTML shape is fixed by `.agents/github-parity.md`: the element stays a
`<blockquote>` (an alert *is* a block quote; GitHub substitutes a `<div>` and
loses that), it carries md4x's `alert alert-<type>` classes *and* GitHub's
`markdown-alert markdown-alert-<type>` so GitHub's class-based CSS matches
unchanged, and a `<p class="markdown-alert-title">` label row opens the block.
The label is derived from the case-folded type name with an initial capital --
one node, one class, one label -- and carries no octicon: the icon is a
stylesheet's business.

## Basic NOTE alert

```````````````````````````````` example
> [!NOTE]
> This is a note
.
<blockquote class="alert alert-note markdown-alert markdown-alert-note">
<p class="markdown-alert-title">Note</p>
<p>This is a note</p>
</blockquote>
````````````````````````````````

## Indented tag is an indented code block, not an alert

The recognizer is gated on `line.indent < CODE_INDENT_OFFSET`. Five spaces
after the `>` leave four columns of indent inside the quote, which opens an
indented code block before the tag is ever considered (md4c #336, `110011e`).

```````````````````````````````` example
>     [!tip]
> foo
.
<blockquote>
<pre><code>[!tip]
</code></pre>
<p>foo</p>
</blockquote>
````````````````````````````````

## Indent boundary: three columns still opens an alert

One space fewer than the case above -- three columns of indent -- is still
below `CODE_INDENT_OFFSET`, so this *is* an alert. The pair pins the exact
boundary.

```````````````````````````````` example
>    [!tip]
> foo
.
<blockquote class="alert alert-tip markdown-alert markdown-alert-tip">
<p class="markdown-alert-title">Tip</p>
<p>foo</p>
</blockquote>
````````````````````````````````

## Paragraph then alert with no blank line between them

A block quote interrupts a paragraph, and the quote it opens is still eligible
to be an alert -- the tag line is the first line of a container opened on that
same line (md4c #334, `56eec98`). The `-` then opens an empty list item.

```````````````````````````````` example
foo
>[!tip]
>-
.
<p>foo</p>
<blockquote class="alert alert-tip markdown-alert markdown-alert-tip">
<p class="markdown-alert-title">Tip</p>
<ul>
<li></li>
</ul>
</blockquote>
````````````````````````````````

## Indented code block before an alert

The pivot line is reset when the code block ends, so the quote that follows is
analyzed fresh and its tag line is recognized (md4c #320, `5f9b246`).

```````````````````````````````` example
    codeblock
> [!note]
> foo
.
<pre><code>codeblock
</code></pre>
<blockquote class="alert alert-note markdown-alert markdown-alert-note">
<p class="markdown-alert-title">Note</p>
<p>foo</p>
</blockquote>
````````````````````````````````

## Blank `>` line before the tag: not an alert

The tag must be on the line that *opens* the quote container. A bare `>` opens
it first, so the tag line is ordinary text (md4c #327, `c9e4a7c`).

```````````````````````````````` example
>
> [!note]
> x
.
<blockquote>
<p>[!note]
x</p>
</blockquote>
````````````````````````````````

## Lazy continuation after the tag

The tag line is disposed of as blank, so nothing is left for the following
unindented line to lazily continue: the alert comes out empty and the text
becomes a sibling paragraph. Surprising, but it matches md4c and is pinned
deliberately.

```````````````````````````````` example
> [!note]
text
.
<blockquote class="alert alert-note markdown-alert markdown-alert-note">
<p class="markdown-alert-title">Note</p>
</blockquote>
<p>text</p>
````````````````````````````````

## Trailing whitespace after the tag

md4x skips blanks before the end-of-line test, so a tag with trailing spaces is
still an alert. (md4c length-matches the tag exactly instead.) The trailing
spaces on the input line below are significant.

```````````````````````````````` example
> [!note]   
> x
.
<blockquote class="alert alert-note markdown-alert markdown-alert-note">
<p class="markdown-alert-title">Note</p>
<p>x</p>
</blockquote>
````````````````````````````````

## Colon after the tag: the line becomes a link reference definition

`[!NOTE]: something` is a well-formed link reference definition, and ref-def
scanning runs before alert detection. The line is consumed and emits nothing at
all -- neither an alert nor visible text. The label is usable afterwards.

```````````````````````````````` example
> [!NOTE]: something
> x
.
<blockquote>
<p>x</p>
</blockquote>
````````````````````````````````

```````````````````````````````` example
> [!NOTE]: /url
> x [!NOTE]
.
<blockquote>
<p>x <a href="/url">!NOTE</a></p>
</blockquote>
````````````````````````````````

## Not an alert: attribute block after the tag

```````````````````````````````` example
> [!NOTE]{.cls}

<p><span class="cls">!NOTE</span>
x</p>
</blockquote>
````````````````````````````````

## Type charset: digits, underscore and leading punctuation

`[a-zA-Z0-9_-]+` is applied uniformly from the first character, so a type may
begin with a digit, a hyphen or an underscore. The name is lowercased into the
class verbatim, with no separator normalization.

```````````````````````````````` example

<p class="markdown-alert-title">V2_note</p>
<p>x</p>
</blockquote>
````````````````````````````````

```````````````````````````````` example

> x
.
<blockquote class="alert alert-123 markdown-alert markdown-alert-123">
````````````````````````````````

## Unknown type is still an alert

md4c rejects any admonition tag outside its fixed five-name table and renders
it literally. md4x accepts arbitrary types by design, so this is a deliberate
divergence from md4c #320.

```````````````````````````````` example
> [!noteX]
> foo
.
<blockquote class="alert alert-notex markdown-alert markdown-alert-notex">
<p class="markdown-alert-title">Notex</p>
<p>foo</p>
</blockquote>
````````````````````````````````

## Alert type longer than the renderer's lowercase chunk buffer

The HTML renderer lowercases `[!TYPE]` into a fixed-size stack buffer and emits
it in chunks. The parser puts no length cap on the type name, so a name longer
than one chunk must come out whole rather than truncated at the buffer size.

```````````````````````````````` example
> [!AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA]
> foo
.
<blockquote class="alert alert-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa markdown-alert markdown-alert-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa">
<p class="markdown-alert-title">Aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa</p>
<p>foo</p>
</blockquote>
````````````````````````````````
