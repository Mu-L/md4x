# GFM Spec — Extension Sections

Examples imported verbatim from the official GitHub Flavored Markdown Spec, so
that MD4X's GFM extensions are checked against the upstream corpus and not only
against the hand-written md4c-inherited suites (`test/spec-tables.txt`,
`test/spec-tasklists.txt`, `test/spec-strikethrough.txt`,
`test/spec-permissive-autolinks.txt`).

**Imported:** the five `(extension)` sections only — Tables, Task list items,
Strikethrough, Autolinks and Disallowed Raw HTML. Those hold 24 of the upstream
file's 672 examples; 17 of the 24 are here.

**Deliberately not imported:** the other 648 examples. They are CommonMark
**0.29**, which is *older* than `test/spec.txt` (CommonMark 0.31.2), so importing
them would duplicate core coverage at a stale spec version. That includes the 19
examples of the core (non-extension) `Autolinks` section: 13 of its 19 inputs are
byte-identical to examples already in `test/spec.txt` and the other 6 are the same
tests with cosmetically refreshed URLs (`http:` → `https:`, renamed hosts). Two of
them — bare `http://example.com` and bare `foo@bar.example.com`, upstream examples
619 and 620, expecting *no* link — additionally contradict the `Autolinks
(extension)` section imported below, which is the behaviour MD4X implements.

Upstream example numbers are recorded above each example so every block can be
traced back to the source file.

## Adjustments made to the imported expected output

Two examples (upstream 279 and 280, task lists) carry an adjusted expected
output. Category: **renderer output shape** — MD4X's HTML renderer emits GitHub's
`class="task-list-item"` / `class="task-list-item-checkbox"` markers and valueless
boolean attributes (`disabled`, `checked`), where GFM 0.29 emits a bare `<li>` and
`disabled=""` / `checked=""`; MD4X also emits no space between `<input>` and the
item text. This is the documented MD4X rendering (`docs/markdown-syntax.md`,
"Extension: Task Lists"); the parse is identical. `normalize.py` sorts attributes
but does not fold `x=""` into `x`, nor collapse the leading space, so the
adjustment has to be made in the file.

No other adjustment was needed. In particular the two categories that
`test/spec.txt` carries — heading `id` attributes and XHTML `<hr />` / `<br />` /
`<img />` void syntax — do not arise: no extension example contains a heading or a
void element.

## Examples excluded because MD4X and GFM 0.29 genuinely disagree

Seven examples are left out rather than silently re-baselined to whatever MD4X
prints. Each is listed here with its upstream number and the disagreement, so the
omission is auditable and none of it is lost.

- **200** (Tables) — a table cell holding a code span with an escaped pipe in it,
  ``| b `\|` az |``. GFM unescapes `\|` to `|` while splitting the row, so the
  escape takes effect even inside a code span: `<code>|</code>`. MD4X
  (like md4c) treats `\|` as an ordinary inline backslash escape, which code spans
  suppress, and emits `<code>\|</code>`. Undocumented divergence.
- **203** (Tables) — a delimiter row with fewer cells than the header row
  (`| abc | def |` over `| --- |`). GFM requires the counts to match and renders
  the whole thing as a paragraph; MD4X (like md4c) lets the delimiter row set the
  column count and builds a one-column table. Undocumented divergence.
- **623, 625, 626, 627** (Autolinks) — MD4X implements md4c's permissive-autolink
  grammar, which is a different design from GFM's: md4c matches a URL by a
  character grammar per component and then requires the character *after* the match
  to be whitespace or one of `)}].!?,;`, whereas GFM extends the match to the next
  whitespace and then trims trailing punctuation. The design is described in
  `test/spec-permissive-autolinks.txt`. The four divergent outcomes are:
  `www.commonmark.org/a.b.` — MD4X keeps the sentence-final `.` inside the path
  (`.` is an ordinary path character in md4c's grammar, only the *host* scan
  rolls a trailing `.` back); `www.google.com/search?q=(business))+ok` — MD4X stops
  the query at the unbalanced `)` and links only `…q=(business)`, GFM keeps
  `))+ok` inside the link; `www.google.com/search?q=commonmark&hl;` — `&hl;` is
  entity-shaped, so MD4X resolves an entity mark there and the whole autolink is
  dropped, GFM trims the entity and links the rest;
  `www.commonmark.org/he<lp` — `<` is not in MD4X's allowed trailing set, so again
  the whole autolink is dropped, where GFM truncates at `<` and links the prefix.
  The last two are the sharper gap: MD4X produces *no* link at all, not a shorter
  one.
- **652** (Disallowed Raw HTML) — GFM's `tagfilter` extension escapes `<title>`,
  `<textarea>`, `<style>`, `<xmp>`, `<iframe>`, `<noembed>`, `<noframes>`,
  `<script>` and `<plaintext>` in raw HTML. MD4X does not implement `tagfilter`
  (neither does md4c) and passes them through. Feature absent, not a parse bug.
