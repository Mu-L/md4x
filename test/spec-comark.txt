# Comark reference suite

Cases mined from the Comark reference implementation's own test corpus. Unlike
CommonMark and GFM, Comark ships no portable `.txt` spec, so these were
extracted from its `SPEC/` fixtures and its vitest suites and re-pinned against
md4x.

## Inline component name validation

Regressions from Comark's `component-name.test.ts`: a component name must
start with a letter or `$`. A colon followed by digits stays plain text --
before the fix `:8100` produced an `['8100', {}]` element and crashed

## Nested components separated by blank-line runs

Regressions for comarkdown/comark#322: a run of two or more blank lines
between siblings inside a nested component used to drop every later sibling
(YAML-props and shorthand forms) or emit a spurious empty paragraph (slot
form). A blank run of any length is one separator, as in CommonMark, and the
enclosing component still closes at its own marker.

## Component wrappers around native blocks

A `::tag` whose name is a plain HTML block element wraps the block that
follows it, and its `{...}` props land on the wrapper.

<!-- comark SPEC/COMARK/attributes/wrapped-blockquote.md -->
```````````````````````````````` example
::blockquote{attr="value"}
> Blockquote paragraph 1 {attr="value"}
>
> Blockquote paragraph 2 {attr2="value2"}
::
.
<blockquote attr="value">
<p attr="value">Blockquote paragraph 1</p>
<p attr2="value2">Blockquote paragraph 2</p>
</blockquote>
````````````````````````````````

<!-- comark SPEC/COMARK/attributes/wrapped-table.md -->
```````````````````````````````` example
::table{attr="value"}
|col1|col2|
|------|------|
|cell1|cell2|
::
.
<table attr="value">
<thead>
<tr>
<th>col1</th>
<th>col2</th>
</tr>
````````````````````````````````
