# Markdown Renderer

Tests for the markdown renderer (`--format markdown`).
Output is clean, standard CommonMark-compatible markdown.
MDC/Comark syntax is converted to HTML tags, frontmatter is removed,
and raw HTML blocks are stripped.

A few sections below assert the JSON or the HTML renderer instead, where the
Comark markdown syntax page pins an AST shape or a rendered result rather than
a round-trip; those examples carry their own `--format=...` line. The heading-id
sections assert HTML under `--heading-ids`, since the anchors are opt-in there
(`MD_HTML_FLAG_HEADING_IDS`) while the AST always carries them.

## Heading id slugging

The slug is generated the way `github-slugger` does, which is the de-facto
reference for GitHub's own anchors (GitHub publishes no specification). The
cases below are taken from that package's `test/fixtures.json`, whose expected
values are scraped from GitHub's real rendering, so they pin behavior that a
naive reimplementation drifts on: ASCII punctuation is dropped outright rather
than folded to a separator, `-` and `_` survive, runs of spaces each become
their own `-`, and nothing is collapsed or trimmed.

```````````````````````````````` example
# exchange.bind_headers(exchange, routing [, bindCallback])

# heading with a - dash

# heading with an _ underscore

# apostrophe’s should be trimmed

# en–dash
.
<h1 id="exchangebind_headersexchange-routing--bindcallback">exchange.bind_headers(exchange, routing [, bindCallback])</h1>
<h1 id="heading-with-a---dash">heading with a - dash</h1>
<h1 id="heading-with-an-_-underscore">heading with an _ underscore</h1>
<h1 id="apostrophes-should-be-trimmed">apostrophe’s should be trimmed</h1>
<h1 id="endash">en–dash</h1>
.
--heading-ids
````````````````````````````````

Spaces are neither collapsed nor trimmed. A leading or trailing space has to
arrive as an entity, since the ATX parser eats literal ones.

```````````````````````````````` example
# &#x20;a&#x20;

# a  b
.
<h1 id="-a-"> a </h1>
<h1 id="a--b">a  b</h1>
.
--heading-ids
````````````````````````````````

Letters outside ASCII are kept and lowercased, not transliterated or dropped.

```````````````````````````````` example
# Привет non-latin 你好
.
<h1 id="привет-non-latin-你好">Привет non-latin 你好</h1>
.
--heading-ids
````````````````````````````````

The slug is built from the heading's *rendered* text: emphasis, code spans and
link labels contribute their content, an entity contributes the character it
resolves to, and raw inline HTML contributes nothing at all.

```````````````````````````````` example
# **Bold** and `code`

# [text](https://example.com)

# A &amp; B

# a <b>x</b> c
.
<h1 id="bold-and-code"><strong>Bold</strong> and <code>code</code></h1>
<h1 id="text"><a href="https://example.com">text</a></h1>
<h1 id="a--b">A &amp; B</h1>
<h1 id="a-x-c">a <b>x</b> c</h1>
.
--heading-ids
````````````````````````````````

An emoji in the heading text is stripped like any other symbol — the separators
that flanked it stay, so the id keeps the gap.

```````````````````````````````` example
# Hello 👋 World

# Lorem ipsum 😭
.
<h1 id="hello--world">Hello 👋 World</h1>
<h1 id="lorem-ipsum-">Lorem ipsum 😭</h1>
.
--heading-ids
````````````````````````````````

```````````````````````````````` example [no-normalize]
# Hello 👋 World
.
{"nodes":[["h1",{"id":"hello--world"},"Hello 👋 World"]],"frontmatter":{},"meta":{"headings":[{"level":1,"text":"Hello 👋 World","id":"hello--world"}]}}
.
--format=json
````````````````````````````````

Invisible characters must never survive into an id — the result has to be
typeable as a URL fragment. Multi-part emoji are the sharp case: a ZWJ sequence
like 👨‍👩‍👧 carries U+200D joiners. The joiners are stripped, so the id matches
what the same heading gets on GitHub.

```````````````````````````````` example
# A 👨‍👩‍👧 B

# E 👨‍💻 F
.
<h1 id="a--b">A 👨‍👩‍👧 B</h1>
<h1 id="e--f">E 👨‍💻 F</h1>
.
--heading-ids
````````````````````````````````

The same applies to the Unicode space separators and to format characters such
as the BOM — a non-breaking or ideographic space is removed outright rather
than becoming a `-`, which is what distinguishes it from U+0020.

```````````````````````````````` example
# a&#x3000;b

# c&#xA0;d

# e&#xFEFF;f
.
<h1 id="ab">a　b</h1>
<h1 id="cd">c d</h1>
<h1 id="ef">e﻿f</h1>
.
--heading-ids
````````````````````````````````

## Heading id de-duplication

A repeated heading takes the next free `-N` suffix. The counter belongs to the
*base* slug, so a run of identical headings numbers 1, 2, 3 rather than
restarting, and a heading whose own text already spells a suffixed form takes
the next free name instead of stealing one already handed out — `# Same 1`
after two `# Same` is `same-1-1`, not `same-1`.

```````````````````````````````` example
# Same

# Same

# Same 1

# Same-1

# Same
.
<h1 id="same">Same</h1>
<h1 id="same-1">Same</h1>
<h1 id="same-1-1">Same 1</h1>
<h1 id="same-1-2">Same-1</h1>
<h1 id="same-2">Same</h1>
.
--heading-ids
````````````````````````````````

The suffix search restarts from the base counter, so a heading that pre-empted
`foxtrot-1` pushes the second `# Foxtrot` all the way to `foxtrot-2`.

```````````````````````````````` example
# Foxtrot 1

# Foxtrot

# Foxtrot
.
<h1 id="foxtrot-1">Foxtrot 1</h1>
<h1 id="foxtrot">Foxtrot</h1>
<h1 id="foxtrot-2">Foxtrot</h1>
.
--heading-ids
````````````````````````````````

The de-duplicator is keyed by an ordinary map lookup, so a heading that slugs to
a JavaScript prototype key is disambiguated like any other.

```````````````````````````````` example
# \_\_proto\_\_

# \_\_proto\_\_
.
<h1 id="__proto__">__proto__</h1>
<h1 id="__proto__-1">__proto__</h1>
.
--heading-ids
````````````````````````````````

```````````````````````````````` example [no-normalize]
# Same

# Same

# Same 1
.
{"nodes":[["h1",{"id":"same"},"Same"],["h1",{"id":"same-1"},"Same"],["h1",{"id":"same-1-1"},"Same 1"]],"frontmatter":{},"meta":{"headings":[{"level":1,"text":"Same","id":"same"},{"level":1,"text":"Same","id":"same-1"},{"level":1,"text":"Same 1","id":"same-1-1"}]}}
.
--format=json
````````````````````````````````

## Heading id case mapping

Case *folding* rather than lowercasing is a deliberate divergence from
`github-slugger`: md4x reuses the parser's fold tables, so `ß` folds to `ss`
where GitHub leaves it, and a Greek final sigma folds to a medial one. Every
md4x entry point agrees with itself, which is what a table of contents needs.

```````````````````````````````` example
# Straße

# Οδός

# ÄÖÜ
.
<h1 id="strasse">Straße</h1>
<h1 id="οδόσ">Οδός</h1>
<h1 id="äöü">ÄÖÜ</h1>
.
--heading-ids
````````````````````````````````

Dotted capital I folds to `i` plus a combining dot above, which is also what
GitHub produces.

```````````````````````````````` example
# İstanbul
.
<h1 id="i̇stanbul">İstanbul</h1>
.
--heading-ids
````````````````````````````````

## Code block metadata

The info string of a fenced code block carries Comark's code-block metadata,
which the JSON renderer publishes as props on the `pre` node. This is the AST
structure the syntax page documents: `language`, `filename`, `highlights` and
the free-form `meta` remainder on `pre`, with a single `code` child whose
`class` is `language-<language>`.

```````````````````````````````` example [no-normalize]
```javascript {1-3} [utils.ts] meta=value
function hello() {
  console.log("Hello")
}
```
.
{"nodes":[["pre",{"language":"javascript","filename":"utils.ts","highlights":[1,2,3],"meta":"meta=value"},["code",{"class":"language-javascript"},"function hello() {\n  console.log(\"Hello\")\n}\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

All metadata can be combined in any order, so the filename may equally come
before the highlight list:

```````````````````````````````` example [no-normalize]
```javascript [utils.ts] {1-3}
function hello() {
  console.log("Hello")
}
```
.
{"nodes":[["pre",{"language":"javascript","filename":"utils.ts","highlights":[1,2,3]},["code",{"class":"language-javascript"},"function hello() {\n  console.log(\"Hello\")\n}\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

"Any order" also covers the free-form remainder: whatever is left after the
recognized tokens becomes `meta`, whether it trails them, sits between them or
leads them.

```````````````````````````````` example [no-normalize]
```js [a.js] {1} extra
code
```
.
{"nodes":[["pre",{"language":"js","filename":"a.js","highlights":[1],"meta":"extra"},["code",{"class":"language-js"},"code\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

```````````````````````````````` example [no-normalize]
```js {1} extra [a.js]
code
```
.
{"nodes":[["pre",{"language":"js","filename":"a.js","highlights":[1],"meta":"extra"},["code",{"class":"language-js"},"code\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

```````````````````````````````` example [no-normalize]
```js extra [a.js] {1}
code
```
.
{"nodes":[["pre",{"language":"js","filename":"a.js","highlights":[1],"meta":"extra"},["code",{"class":"language-js"},"code\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

The four documented highlight syntaxes — a single line, a range, a list, and
ranges and lines combined — all expand to a flat, ascending array of line
numbers.

```````````````````````````````` example [no-normalize]
```js {3}
a
b
c
```
.
{"nodes":[["pre",{"language":"js","highlights":[3]},["code",{"class":"language-js"},"a\nb\nc\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

```````````````````````````````` example [no-normalize]
```js {1-5}
a
```
.
{"nodes":[["pre",{"language":"js","highlights":[1,2,3,4,5]},["code",{"class":"language-js"},"a\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

```````````````````````````````` example [no-normalize]
```js {1,3,5}
a
```
.
{"nodes":[["pre",{"language":"js","highlights":[1,3,5]},["code",{"class":"language-js"},"a\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

```````````````````````````````` example [no-normalize]
```js {1-3,7,10-12}
a
```
.
{"nodes":[["pre",{"language":"js","highlights":[1,2,3,7,10,11,12]},["code",{"class":"language-js"},"a\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

A backslash escapes a special character inside a filename, so brackets can
appear in it; the escape itself is removed.

```````````````````````````````` example [no-normalize]
```typescript [@[...slug\].ts]
// Brackets and special chars are supported
```
.
{"nodes":[["pre",{"language":"typescript","filename":"@[...slug].ts"},["code",{"class":"language-typescript"},"// Brackets and special chars are supported\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

The metadata scanner only engages after a language token. With no language, the
whole info string is the language — including the brackets, which then reach
the CSS class.

```````````````````````````````` example [no-normalize]
``` [a.js]
code
```
.
{"nodes":[["pre",{"language":"[a.js]"},["code",{"class":"language-[a.js]"},"code\n"]]],"frontmatter":{},"meta":{"headings":[]}}
.
--format=json
````````````````````````````````

## Emojis

Emoji shortcodes (`:emoji_name:` -> the emoji character) are a **build-time
opt-in**: the 1913-entry table costs ~26 KB gzipped on the standalone bundle, so
no shipped artifact carries it. Build with `-Demoji=true` to turn the feature
on; the examples below pin the default build, where a shortcode is ordinary text
and reaches the output verbatim.

```````````````````````````````` example [no-normalize]
Hello :wave: Welcome to our docs! :rocket:
.
<p>Hello :wave: Welcome to our docs! :rocket:</p>
````````````````````````````````

```````````````````````````````` example [no-normalize]
:smile: :heart: :fire: :rocket: :sparkles: :tada:
:thinking: :eyes: :100: :star: :zap: :bulb: :warning:
.
<p>:smile: :heart: :fire: :rocket: :sparkles: :tada:
:thinking: :eyes: :100: :star: :zap: :bulb: :warning:</p>
````````````````````````````````

## Escaping

Text that would be read back as markup is re-escaped, so the output re-parses
to the same document. Everything below is checked to render the same HTML
before and after the markdown round-trip.

```````````````````````````````` example [no-normalize]
\# not a heading

\- not a list item

\> not a quote
.
\# not a heading

\- not a list item

\> not a quote
.
-t markdown
````````````````````````````````

```````````````````````````````` example [no-normalize]
text with \`backtick\` and \_underscore\_ and \*star\*
.
text with \`backtick\` and \_underscore\_ and \*star\*
.
-t markdown
````````````````````````````````

A `"` in a link title used to terminate the title early and destroy the link.

```````````````````````````````` example [no-normalize]
[t](/a "ti\"tle")
.
[t](/a "ti\"tle")
.
-t markdown
````````````````````````````````

A destination is wrapped in `<...>` only when it carries whitespace; otherwise
parentheses are backslash-escaped so it stays readable.

```````````````````````````````` example [no-normalize]
[a](/x?y=1&z=2) and [b](/a(b)c) and [c](</a b>)
.
[a](/x?y=1&z=2) and [b](/a\(b\)c) and [c](</a b>)
.
-t markdown
````````````````````````````````

longest backtick run in the content instead.

```````````````````````````````` example [no-normalize]

-t markdown
````````````````````````````````

`_`, `~` and `$` only become marks when they are not surrounded by word
characters, so intra-word ones are left alone.

```````````````````````````````` example [no-normalize]
snake_case and file~name and cost$s
.
snake_case and file~name and cost$s
.
-t markdown
````````````````````````````````

A `=` is markup only in a run of two (`==highlight==`), and that run is
whitespace-flanked rather than word-flanked, so every `=` next to another `=`
is escaped while a lone one is left alone.

```````````````````````````````` example [no-normalize]
a = b and 2 ==2 and x \=\= y
.
a = b and 2 \=\=2 and x =\= y
.
-t markdown
````````````````````````````````

A real highlight span is re-emitted as `==`.

```````````````````````````````` example [no-normalize]
a ==hi== and b==c==d
.
a ==hi== and b==c==d
.
-t markdown
````````````````````````````````

An entity is resolved to its character, which then needs escaping of its own:
`&amp;amp;` must not come back out as a bare `&amp;`.

```````````````````````````````` example [no-normalize]
&amp;amp; is an escaped entity
.
&amp;amp; is an escaped entity
.
-t markdown
````````````````````````````````

A trailing `#` run would close an ATX heading.

```````````````````````````````` example [no-normalize]
# heading with a \#
.
# heading with a \#
.
-t markdown
````````````````````````````````

## Footnotes

A reference round-trips as `[^label]`. The definition is re-emitted at the end
of the document, which is where the parser hands it over — a textual move, not
a semantic one.

```````````````````````````````` example [no-normalize]
Text[^1] and again[^1].

[^1]: The note.
.
Text[^1] and again[^1].

[^1]: The note.
.
-t markdown
````````````````````````````````

Definitions move to the end even when they were written first, and follow
first-reference order rather than definition order.

```````````````````````````````` example [no-normalize]
[^b]: B note.
[^a]: A note.

See [^a] then [^b].
.
See [^a] then [^b].

[^a]: A note.

[^b]: B note.
.
-t markdown
````````````````````````````````

A literal `[^1]` with no definition is not a reference, and `[` is escaped
unconditionally, so it cannot become one on the re-parse.

```````````````````````````````` example [no-normalize]
Not a ref: [^1].
.
Not a ref: \[^1\].
.
-t markdown
````````````````````````````````
